8-6　MCP のつなぎ方と置き場所

ゴール手元での接続とネットワーク越しの接続を、置き場所と共有の仕方で選び分けられる。

MCP のクライアントとサーバをつなぐ方式（トランスポート）は、公式には2つです。手元で子のプロセスとして動かすか、ネットワークの向こうに置くかで選びます。

DOMAIN 8MCP Server Development

観点stdioStreamable HTTP
置き場所同じ機械の中ネットワークの向こう
起動クライアントが、子のプロセスとして起動するサーバが、自分で動き続ける
通り道標準入出力（1行に1つの JSON-RPC）1つの URL への HTTP のリクエスト
つなぐ数ふつうは1つ多くのクライアント
認証鍵は環境変数から読むHTTP の認証。OAuth が勧められている
向く使い方手元のファイルや道具を、自分だけで使う社内の仕組みを、チームや複数のアプリで共有する

ポイント手元で1人が使うなら stdio、ネットワーク越しに皆で使うなら Streamable HTTP。

つなぎ方ごとの決まり

ゴールそれぞれのつなぎ方で守ることを言える。

stdio では、標準出力がそのままやり取りの通り道です。サーバが標準出力にログを書くと、やり取りが壊れます。ログは標準エラーに出します。

ネットワーク越しのサーバは、どこからでも呼ばれうる入口になります。認証を付け、受け取ったトークンが自分宛てかを確かめます。接続ごとに Origin ヘッダも確かめます（仕様上の必須）。手元で HTTP のサーバを動かすときは、外から届かないアドレス（127.0.0.1）で待ち受けます。

古い方式（HTTP と SSE を組み合わせたもの）は非推奨で、新しく作るサーバは Streamable HTTP を使います。公式の方式はこの2つですが、ソケット（Unix ドメインソケットや TCP）の上に独自のつなぎ方を作ることも、仕様上は認められています。その場合は、stdio と同じ「1行に1つの JSON-RPC」の形を使うよう勧められています。

どこに置き、誰と共有するか

ゴールClaude Code で、MCP サーバの設定をどの範囲に置くかを選べる。

範囲置き場所効くところ
local既定。自分の設定（~/.claude.json）の、そのプロジェクトの欄自分だけ・そのプロジェクトだけ
projectプロジェクト直下の .mcp.jsonバージョン管理で、チーム全員に配れる。対話のセッションでは、使う前に承認を求められる
user自分の設定（~/.claude.json）自分の、すべてのプロジェクト

※ .mcp.json には鍵を直接書かず、${API_KEY} のように環境変数で書きます（読み込むときに展開される）。鍵の扱いは〈鍵と秘密の置き場所〉で扱います。
