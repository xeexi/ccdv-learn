8-2　実行するのはアプリ ─ 呼び出しの配り方

ゴールtool_use を受けてからの流れと、クライアント側・サーバ側のツールの違いを説明できる。

アプリ→Claude→アプリ

Claude は道具を「頼む」だけで、実行するのはアプリです。頼まれた呼び出しを、名前から自分の関数へ振り分けて実行し、結果を返す。この往復が、ツールを使う1周です。

DOMAIN 8Tool Implementation

振り分ける部分 ─ ハーネス

ゴールアプリの中で、呼び出しを関数へ振り分ける部分の役目を言える。

tool_use を受け取って関数へ振り分け、結果を返す部分をハーネスと呼びます。ここが担うのは、名前から関数を選ぶこと、引数を確かめること、失敗を結果の形にすること、そして1つの応答に並んだ呼び出しの結果を、すべて1つのメッセージにまとめて返すことです。

このループは、SDK の tool runner に任せることもできます。道具の関数を渡すと、呼び出し・実行・結果の返送を繰り返し、Claude が道具を頼まなくなったところで止まります。

クライアント側と、サーバ側

ゴール実行する場所で、ツールを見分けられる。

種類実行する場所例アプリがすること
クライアント側自分のアプリ自作のツール。Anthropic が形を決めた bash・text editor・memory も、実行はアプリ実行して、tool_result を返す
サーバ側Anthropicweb search・web fetch・code executiontools に宣言するだけ。結果は同じ応答の中に入って返る

サーバ側の道具は、Anthropic の中で呼び出しと実行を繰り返します。長くかかると、途中で止めた印（pause_turn）付きで応答が返るので、そのまま送り返して続けさせます。

外のシステムにつなぐ設定

ゴール外のシステムへの接続の情報を、どこに置くかを言える。

ツールの中身が社内の API やデータベースを呼ぶとき、接続先・鍵・待ち時間の上限は、アプリ側の設定に置きます。ツールの定義やプロンプトには書きません。Claude が見るのは名前・説明・入力の形だけで、鍵を知る必要はありません。

同じ接続を複数のアプリで使い回したいなら、ツールを MCP サーバとして切り出します（〈MCP サーバが出すもの〉）。

ポイントClaude は頼むだけで、実行も鍵もアプリの側にある。サーバ側の道具だけは、Anthropic が実行する。
