8-8　Skills か、MCP か

ゴール手順の再利用と外のシステムへの接続で、Skills と MCP を使い分けられる。

残る2つの手は、足すものが違います。MCP は外のサービスへの接続を足し、Skills は知識と手順を足します。

DOMAIN 8Agentic Customization

手足すもの形向くとき
MCP外のサービスへの接続（道具とデータ）アプリの外のサーバ。複数のアプリから共有できる社内の仕組みを、いくつものアプリから使い回す
Skills知識・手順・参照資料名前と説明を持つ SKILL.md と、付属の資料のフォルダ決まった手順（報告書の書式、社内の作法など）を、必要なときだけ読ませる

ポイントMCP はつなぐ、Skills は教える。組み合わせるなら、MCP で接続し、Skills でその使い方を教える。

Skills は、必要になるまで読まない

ゴールSkills を増やしても文脈を圧迫しにくい理由を言える。

Skills は3段階で読み込まれます。ふだん文脈に入っているのは名前と説明だけです。仕事がその Skill に当てはまると本文（SKILL.md）が読まれ、付属の資料は要るときだけ開かれます。だから Skills をたくさん用意しても、使っていないものは窓をほとんど食いません。

同じ形の Skill を Claude Code・Agent SDK・API から使えますが、置き場所は使う側ごとに違い、自作の Skill が自動で行き渡ることはありません。

4つの手の選び方

ゴール場面に合わせて、4つの手から1つを選べる。

選ぶ手場面
組み込みのツール公開されている最新の情報を調べる、コードを動かす
自作のツールこのアプリだけで、社内の API を呼ぶ
MCP同じ社内の仕組みを、複数のアプリから使う
Skills決まった手順や作法を、必要なときに守らせる

※ 公式の例題にも、社内の REST API を複数のアプリから使い回す場面が出ます。戻り先は〈公式の例題〉にまとめてあります。
