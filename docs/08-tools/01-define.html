8-1　ツールを渡すとは、説明書を渡すこと

ゴール名前・説明・入力の形が選ばれ方をどう決めるかを説明し、ツールの組をそろえられる。

アプリ→Claude

Claude は、ツールを自分で動かせません。アプリが渡すのは「こういう道具がある」という説明書で、Claude はそれを読み、使いたいときに「この道具を、この引数で」と頼みます。この仕組みがツール使用（関数呼び出し）です。

DOMAIN 8Tool Implementation

ツールの定義 ─ リクエストの tools に並べる

{ "name": "get_order",1
  "description": "注文の状態を調べる。利用者が配送や注文の状況を尋ねたときに使う。",2
  "input_schema": {
    "type": "object",
    "properties": {
      "order_id": { "type": "string",
        "description": "注文番号。例: A-1024" },3
      "detail": { "type": "string",
        "enum": ["summary", "items"] } },
    "required": ["order_id"] } }4
  1. 1名前は、何をするかが分かる具体的なものにする。
  2. 2説明には「何をするか」だけでなく「いつ使うか」を書く。Claude は主にこれを読んで選ぶ。
  3. 3引数ごとにも説明を付ける。決まった値しか取らない引数は、enum で絞る。
  4. 4本当に必要な引数だけを required にする。

ポイントClaude が見ているのは、名前・説明・入力の形の3つだけ。選び間違いの多くは、説明の書き方で直る。

呼ばれると、応答は tool_use で止まる

ゴールツールを渡したときに、応答がどう変わるかを言える。

Claude がツールを使うと決めると、応答には答えの文章の代わりに tool_use という種類のブロック（道具の名前・引数・呼び出しごとの id）が入り、stop_reason も tool_use になります。ここで止まるのは、実行するのがアプリだからです。アプリが実行して結果を tool_result として返すと、Claude は続きを書けます（流れは〈実行するのはアプリ〉）。

tool_choiceClaude の振る舞い
auto既定。使うかどうかを、Claude が決める
anyどれか1つは必ず使う
tool名前で指定した道具を、必ず使う
none使わない

1つの応答に tool_use が複数並ぶこともあります（並列の呼び出し）。使うことを強制する指定（any・tool）を受け付けないモデルもあるので、そのときは auto にして、どの道具を使ってほしいかをプロンプトで伝えます。

ツールの組をそろえる

ゴールツールの数と粒度を、選び間違いの起きにくい形に決められる。

起きること直し方
取り違え説明に、違いと使い分けを書く。役目が重なるなら1つにまとめる
数の多さその仕事に要るものだけに絞る。多いときは、必要な定義だけを探して読み込ませる（tool search）
細かすぎいつも続けて使う操作は、1つの道具にまとめる
引数の誤り型と enum で取りうる値を絞り、引数の説明に例を書く。strict: true を付けると、引数が形どおりになることを保証できる

ポイントツールの組は「少なく、重ならず、名前と説明で見分けがつく」形にそろえる。
