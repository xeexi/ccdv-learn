2-2　データの渡し方と、呼び出し口

ゴール資料の渡し方と、他社のクラウド経由で呼ぶときの違いを説明できる。

アプリ→Claude

Claude に資料を読ませる道は2つあります。リクエストに載せて渡すか、道具で取りに行かせるかです。載せて渡すなら、中身を直接入れるか、URL を示すか、先に上げておいたファイルの ID を指します。

DOMAIN 2Claude API Mechanics

渡し方書き方向くとき
直接画像や PDF は base64 にして、文章はそのまま入れる1回きりの資料
URLネットにある場所を指す公開されている資料
ID で指すFiles API に一度上げ、ID で指す同じ資料を何度も使う
道具で取るWeb の取得・社内の検索・MCP で、要るときに読ませる量が多く、どれが要るか先に分からない

ポイント1回きりなら直接、何度も使うならファイル ID、量が多いなら道具で取りに行かせる。どの渡し方でも、窓に入った分は入力トークンとして数える。

Files API で、一度上げて使い回す

ゴールFiles API を使う理由と、数え方の注意を言える。

Files API にファイルを一度上げると、以後は ID を書くだけで、画像（image）や文書（document）のブロックに使えます。大きな資料を毎回送り直さずに済みます。上げるだけなら料金はかからず、メッセージで使った分が、入力トークンとして数えられます。ファイルは、上げるときに期限を付けなければ、消すまで残ります。

資料の渡し方と、資料の読み方は別の話です。長い資料は質問より先に置き（〈指示は system に、材料は user に〉）、出典を示させたいなら文書ブロックで引用の機能を使います。

他社のクラウド経由で呼ぶ

ゴールAmazon Bedrock・Google Cloud・Microsoft Foundry、Claude Platform on AWS 経由で呼ぶときの違いを言える。

Claude は、Anthropic の API のほかに、他社のクラウドからも呼べます。社内の契約や請求、認証の仕組みを1つのクラウドにまとめたいときに使います。SDK には各クラウド用のクライアントがあり、呼び出しの形（messages.create）は同じです。

経路は、運営する者で2つに分かれます。Amazon Bedrock・Google Cloud・Microsoft Foundry は、そのクラウドの会社が推論を運営します。Claude Platform on AWS は、AWS のアカウントと請求から入りますが、運営するのは Anthropic で、機能はたいてい Claude の API と同じ日に届きます。

違い中身
認証Anthropic の API キーではなく、そのクラウドの認証と権限の仕組みを使う
IDモデルの ID の書き方が、クラウドごとに違う（Claude Platform on AWS は Claude の API と同じ）
機能他社が運営する経路では、新しい機能やベータの機能は、使えないか、遅れて届くことがある。Batch は Claude の API と Claude Platform on AWS でしか使えない
請求そのクラウドの請求にまとまる
誤解「どのクラウド経由でも、Anthropic の API と同じ機能が同じ日に使える」 実際は他社が運営する経路では、使える機能と、届く時期が違う。設計の前に、使う経路でその機能が使えるかを確かめる。
