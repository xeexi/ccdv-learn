2-16　入出力の形を設計する

ゴールツールや出力の形を、間違えにくい形に設計できる。

道具の引数も、構造化出力の応答も、形は JSON Schema で決めます。形の設計は、プロンプトの言葉を足すより確実に、表記の揺れと作り話を減らします。決めるのは、正しい値の形と、迷ったときの逃げ道の両方です。

DOMAIN 2Claude Application Design

請求書から抜き出す形

"properties": {
  "amount_jpy": { "type": "integer" },1
  "category": { "type": "string",
    "enum": ["物品", "役務", "その他"] },2
  "detail": { "type": "string" },
  "due_date": { "type": ["string", "null"],
    "format": "date", "description": "無ければ null" } },3
"required": ["amount_jpy", "category"]4
  1. 1型と単位を、型と名前で絞る。「1,200円」のような文字列は入らない。
  2. 2選択肢を閉じ、「その他」と自由に書ける欄を逃げ道に置く。無いと、近い分類へ無理に押し込まれる。
  3. 3見つからないときに「無い」と書けるようにする。書けないと、それらしい値を作られる。
  4. 4必ず埋まるものだけを必須にする。
決まり中身
型を絞る数値や真偽を、文字列で受けない
閉じる決まった選択肢は enum にする。表記の揺れが消える
逃げ道「その他」や「無い」を選べるようにする
名前曖昧な名前を避ける（user より user_id）。単位や形式は、名前か説明に書く
指示と組む日付は "format": "date" で形をそろえられる。型でも形式でも縛れない揺れ（会社名の表記など）は、そろえ方を指示に書く

ポイント形の設計は、正しい値の形と逃げ道の両方を決めること。逃げ道が無いと、Claude はそれらしい値で埋める。

道具の結果の形

ゴール道具が返す結果を、次の判断に使いやすい形にできる。

決まり中身
項目次の判断に効く項目だけを返す。使わない項目や内部の技術的な値は省く
名前意味のない英数字の ID より、名前や題を返す。次の呼び出しに要る ID は残す
量件数の上限・絞り込み・ページ分けを用意し、既定値を小さめにする
詳しさ引数で「簡潔」か「詳細」かを選べるようにする
失敗何が悪く、どう直せばよいかを書く（〈失敗の返し方と、承認の挟み方〉）
誤解「項目を多く返すほど、Claude は正しく判断できる」 実際は使わない項目や意味のない ID は、窓を食い、判断を迷わせる。次の判断に効くものに絞る。
