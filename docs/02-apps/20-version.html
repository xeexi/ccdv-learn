2-20　版を固定する ─ モデル・プロンプト・プラグイン

ゴール変更で壊れないように、モデル・プロンプト・プラグインの版を扱える。

Claude のアプリは、モデル・プロンプト・プラグインのどれが変わっても、挙動が変わります。変わる部品の版を固定し、変えるときは評価で確かめてから替えます。

DOMAIN 2Configuration Management

部品固定のしかた変えるとき
モデルモデル ID を指定する。ID ごとに、中のモデルは固定されている新しい ID を評価で確かめてから切り替える
プロンプトコードと同じリポジトリで、版として管理する前の版と同じテストで比べてから替える
プラグインplugin.json の version。取り込む元は git の ref や sha で固定できるversion を上げて配る

ポイント変わる部品は版を固定し、替えるときは前の版と同じテストで比べる。固定しないと、何が挙動を変えたのかをたどれない。

モデルの ID と、引退

ゴールモデル ID と別名の違いと、引退への備えを言える。

Claude のモデル ID は、それぞれ固定された版を指します。同じ ID なら、中のモデルは変わりません。古い世代には、最新の日付つきの版を指す短い別名もあります。Claude Code の opus や sonnet のような別名は、時とともに指す先が変わるので、固定したいなら ID を書くか、対応する環境変数で指定します。

モデルは、提供中 → 非推奨（引退の日と代わりのモデルが示される）→ 引退、と進みます。引退したモデルへのリクエストは失敗します。

誤解「モデル ID を固定しておけば、いつまでも同じモデルを使い続けられる」 実際は固定しても、引退すれば呼べなくなる。非推奨の知らせを追い、乗り換えを評価で確かめる（〈作って終わりではない〉）。

プロンプトとプラグインの版

ゴールプロンプトとプラグインを、壊さずに更新する方法を言える。

プロンプトは、コードと同じリポジトリで管理し、変えるたびに前の版と同じテストで比べます（〈直しながら寄せる〉）。どの版のプロンプトを、どのモデルに送ったかを記録しておくと、挙動が変わったときに原因をたどれます。Managed Agents では、モデル・system・道具の組（agent）そのものに版が付きます。

プラグインは、plugin.json の version を上げて配ります。version を変えずに中身だけ更新しても、利用者は手元に残った古い写しを使い続けます。ほかのプラグインに頼るなら、依存（dependencies）として、試した版の範囲（^2.0 など）を書きます。
