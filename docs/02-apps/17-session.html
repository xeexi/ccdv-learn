2-17　セッションとプラグインを管理する

ゴール会話を分ける・捨てる判断と、プラグインの入れ方・外し方を説明できる。

開発者→Claude Code

会話が長くなるほど、窓には関係のない試行や失敗が積もり、出来が落ちます。会話をいつ分け、いつ捨てるかを決めておくのが、セッションの衛生（session hygiene）です。

DOMAIN 2Claude Application Design

場面手
別の仕事別の仕事に移るときは、/clear で文脈を空にする
直らない同じことを2回より多く直させても駄目なら、/clear し、学んだことを入れた具体的なプロンプトで始め直す
戻りたい/rewind で、会話とコードを前の時点に戻す。git の代わりにはならない
続き--continue（直前の会話）か --resume（一覧から選ぶ）で再開する
長い/compact で要約して、窓を空ける（〈窓を守る〉）

ポイント失敗が積もった長い会話より、学んだことを入れて始め直した短い会話のほうが、ほとんどの場合うまくいく。

API のアプリでも同じです。新しい仕事は、前の仕事の履歴を引きずらずに、新しい会話で始めることを考えます。

プラグインを管理する

ゴールプラグインの入れ方・広げ方・外し方と、信頼の注意を言える。

プラグインは、Skills・子の定義・フック・MCP サーバ・コマンドなどを1つにまとめて配る単位です。プラグインの一覧（マーケットプレイス）から、/plugin で入れ、有効にし、無効にし、更新し、外します。

範囲有効にした記録の場所効くところ
user~/.claude/settings.json自分の、すべてのプロジェクト
project.claude/settings.jsonリポジトリを使う全員（git で共有）
local.claude/settings.local.json自分だけ・そのリポジトリだけ

チームで同じプラグインを使うなら、リポジトリの .claude/settings.json に、マーケットプレイス（extraKnownMarketplaces）と有効にするプラグイン（enabledPlugins）を書いて配ります。

誤解「プラグインは Claude への指示を足すだけなので、入れても危険はない」 実際はフックや MCP サーバを含められ、自分の権限で任意のコードを動かせる。信頼できる出どころのものだけを入れる。
