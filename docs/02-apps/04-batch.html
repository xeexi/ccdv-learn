2-4　まとめて安く ─ Batch API

ゴール待てる大量処理は Batch、すぐ要る処理は通常の呼び出し、と選び分けられる。

アプリ→Claude→アプリ

すぐに答えが要らない大量の処理は、Message Batches API にまとめて送れます。料金は通常の半額で、結果は後から取りに行きます。

DOMAIN 2Claude API Mechanics

比べる点通常の呼び出しBatch
届く時間すぐ。逐次なら最初の文字から多くは1時間以内、長くて24時間
料金通常半額
向く仕事利用者が画面で待っている評価の一括実行、ためた文書の分類や抽出
制約─逐次では受け取れない。fast mode も使えない。サーバ側の道具は1件の中で回るが、自前の道具を実行して続きを回すことはできない

ポイント選ぶ基準は「すぐ答えが要るか」。件数の多さではない。要らないなら、半額で回せる。

custom_id で突き合わせる

ゴール結果を取り違えずに受け取る方法を言える。

Batch に入れる1件

{ "custom_id": "inv-001",1
  "params": { "model": "…",
    "max_tokens": 1024,
    "messages": [ … ] } }2
  1. 11件ごとに付ける自分の ID。結果は送った順に返るとは限らないので、この ID で突き合わせる。
  2. 2中身は、通常の Messages API のリクエストと同じ。道具・画像・キャッシュも使える。
1件の結果意味次の手
succeeded成功した結果を使う
errored失敗した入力の誤りなら直して、サーバ側の失敗ならそのまま送り直す
canceled取り消した要るなら送り直す
expired期限内に終わらなかった送り直す

締め切りと、試し流し

ゴール締め切りのある仕事で、Batch に回す間隔と進め方を決められる。

Batch は、長ければ24時間かかります。「受け取ってから30時間以内に返す」約束なら、ためてから送るまでに使えるのは6時間までで、実際には余裕を見てもっと短い間隔で送ります。「1日に1回まとめて」は、締め切りのある仕事では成り立たないことがあります。

全件を流す前に、少ない件数で試し、プロンプトを直してから本番を流します。やり直しは、結果が返るまで待つ分だけ高くつきます。

誤解「件数が多い処理は、Batch にすべき」 実際は基準は件数ではなく、すぐ答えが要るか。利用者が待っているなら、件数にかかわらず通常の呼び出しを使う。
