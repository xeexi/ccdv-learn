2-6　REST と JSON

ゴールREST の作法と JSON の形で、API のやり取りを読める。

REST は、Web の API をつくる作法です。操作したい対象を URL で表し、何をするかを HTTP のメソッドで、結果をステータスコードで表します。本文には JSON がよく使われます。Claude の API も、アプリの道具が呼ぶ社内の API も、この作法の上にあります（Claude の API の実物は〈SDK は REST を包んでいる〉）。

DOMAIN 2Software Engineering Foundations

メソッドすること同じ要求を繰り返すと
GET取得する状態は変わらない
POST作る・処理を頼むそのたびに新しく作られうる
PUT丸ごと置き換える何度送っても同じ状態になる
PATCH一部を変える書き方しだい
DELETE消す何度送っても消えたまま

ポイント再試行してよいかは、繰り返しても結果が変わらないか（冪等か）で決まる。POST を再試行するなら、二重に作らない工夫と組にする。

ステータスコードの読み方

ゴールステータスコードの範囲から、誰の誤りで、再試行してよいかを言える。

範囲意味例と、次の手
2xx成功200 など。本文を読む
4xx送った側の誤り400 形の誤り、401 認証、403 権限、404 見つからない。直してから送る。429（送りすぎ）は、たいてい間を空ければ通る
5xx受けた側の不調間を空けて再試行してよい

429 の応答には、待つ秒数（retry-after）が付くことがあります。待たずに送り直すと、同じ理由で断られ続けます。ただし Claude の API では、月の支出の上限に達したときも 429 が返ります。このときは retry-after が付かず、上限が戻るまで待っても通りません。Claude の API に特有のエラーと立て直し方は〈エラーの種類と、立て直し方〉で扱います。

JSON の形

ゴールJSON の型と、壊れにくい作り方を言える。

JSON の型

{ "order_id": "A-1024",1
  "items": [ { "sku": "X1", "qty": 2 } ],2
  "paid": true,
  "note": null }3
  1. 1全体はオブジェクト。名前は必ず二重引用符で囲んだ文字列。
  2. 2配列の中にオブジェクト。数値は引用符で囲まない。
  3. 3真偽（true・false）と、値が無いこと（null）。注釈や末尾のカンマは書けない。

JSON は、文字列をつなげて組み立てず、必ずパーサ（Python の json など）で作り、パーサで読みます。どの項目が必須で、どんな値を取るかは、JSON Schema で決めておきます（〈入出力の形を設計する〉）。

誤解「JSON なら、文字列をつなげて作っても同じ」 実際は値に引用符や改行が入ると、その場で壊れる。作るのも読むのも、パーサに任せる。
