2-14　入口ごとに、指示の読まれ方が違う

ゴールClaude Code・Desktop・claude.ai・API・SDK で、指示がどこから入るかを言える。

同じ Claude でも、どの入口から使うかで、こちらの指示の前に何が入っているかが違います。この違いを知らないと、ある場所で効いた指示が、別の場所で効かない理由が分かりません。

入口前から入っている指示こちらの指示の入り方
API無い（Client SDK で呼んでも同じ）。道具を渡したときだけ、道具を使うための指示が足されるアプリが system と messages を毎回書く。会話の履歴もアプリが送る
claude.aiWeb と Desktop のアプリの会話。Anthropic が用意した system プロンプトがあるアカウント全体の指示・プロジェクトの指示（そのプロジェクトの会話だけに効く）・Skills（口調や書式もこれで変える）。記憶もプロジェクトごと
Claude CodeClaude Code 自身の system プロンプト（利用者には見えない）CLAUDE.md が、system の後に user のメッセージとして入る。道具の結果は会話に積まれる
Agent SDK最小限の system プロンプト（道具の使い方だけ）自分の system を書くか、Claude Code のものを指定して追記する。設定ファイルを読むかも選べる

ポイントAPI は自分が書いたものだけで始まる。claude.ai や Claude Code は、前から入っている指示の上に、こちらの指示が載る。入口を移すときは、足りない前提を自分で書き足す。

Claude Code と Agent SDK

ゴールClaude Code と Agent SDK で、既定の指示と読み込む設定がどう違うかを言える。

Claude Code は、自分の system プロンプトの後に、CLAUDE.md を user のメッセージとして入れます。Claude は読んで従おうとしますが、曖昧な指示や、互いに矛盾する指示は守られるとは限りません。必ず守らせたいことは、フックや権限の設定に置きます（〈決まった処理はフックで〉）。

Agent SDK は、既定では道具の使い方だけを書いた最小限の system プロンプトで動き、Claude Code の安全の指示や作業環境の説明は入りません。Claude Code と同じ振る舞いが欲しいなら、Claude Code の system プロンプトを指定し、足したい決まりはその後ろに追記します。

入口を移すとき

ゴールある入口で効いたプロンプトを、別の入口に移すときの注意を言える。

claude.ai で試したプロンプトを API のアプリに移すと、Anthropic の system プロンプトの支えが無くなります。役割・口調・前提を自分の system に書き足し、同じテストで確かめてから出します。逆に、claude.ai のプロジェクトの指示は、そのプロジェクトの外の会話には効きません。

誤解「claude.ai で上手くいったプロンプトは、API に移してもそのまま同じように動く」 実際はclaude.ai には Anthropic の system プロンプトがあり、API には無い。移すときは前提を書き足し、評価で確かめる。
