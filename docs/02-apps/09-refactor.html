2-9　リファクタリングを任せる ─ 小さく・大きく

ゴール小さな書き換えと大きな作り直しで、任せ方と確かめ方を選び分けられる。

開発者→Claude Code→開発者

リファクタリングは、振る舞いを変えずに中身を書き換えることです。振る舞いが変わっていないことはテストで確かめ、変更の大きさによって任せ方を変えます。

DOMAIN 2Software Engineering Foundations

比べる点小さな書き換え大きな作り直し
例1つの関数を分ける、名前をそろえる数百のファイルで、古いライブラリの呼び出しを新しい書き方に移す
計画差分を1文で言えるなら、計画は省く先に調べて計画を立て、合意してから動かす
進め方テストで確かめられる小さな単位で、少しずつ進める仕事を分けて、並行に進める
確かめ方いまのテストを流す。無ければ先に書く単位ごとにテストを流し、失敗したものだけやり直す

ポイント振る舞いを変えないことは、テストで確かめる。小さな書き換えは計画を省いて小刻みに、大きな作り直しは計画してから分けて並べる。

大きな作り直しの進め方

ゴール大規模な移行を、分けて並べて確かめる手順を言える。

Claude Code の /batch は、変更を分けて子に任せ、子はそれぞれ別の worktree で作業します。自分のスクリプトからファイルごとに対話なしで回すときは、使える道具を絞っておきます。後方互換を保つ必要があるなら、そう指示に書きます。

テストを先に

ゴールテストの無いコードを書き換えるときの順番を言える。

テストの無いコードを書き換えるなら、先にいまの振る舞いを固定するテストを書かせてから、書き換えさせます。不具合を直すときも、まず再現する（失敗する）テストを書かせ、それが通るように直させます。

誤解「大きな移行は、1つの長いセッションで一気にやらせるのが速い」 実際は窓が尽き、どこで崩れたかも追えなくなる。一覧にして分け、単位ごとに確かめる。
