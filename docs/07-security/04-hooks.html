7-4　壊す操作はフックで止める

ゴール取り返しのつかない操作を、フックで確実に止める形を説明できる。

Claude→フック→ツール

ファイルの一括削除や、履歴を書き換える push のような取り返しのつかない操作は、頼んで避けさせるのではなく、実行の手前で止めます。PreToolUse のフックは道具が動く前に呼ばれ、止めると決めた呼び出しを止めます（フックの基本は〈決まった処理はフックで〉）。

DOMAIN 7Claude Hooks

.claude/settings.json ─ Bash のたびに呼ぶ

{ "hooks": { "PreToolUse": [{
    "matcher": "Bash",1
    "hooks": [{ "type": "command",
      "command": "${CLAUDE_PROJECT_DIR}/.claude/hooks/guard.sh" }] }] } }

.claude/hooks/guard.sh ─ 呼ばれるスクリプト

cmd=$(jq -r '.tool_input.command')2
case "$cmd" in
  *"rm -rf"*|*"push --force"*)
    echo "破壊的な操作は止めました" >&2
    exit 2 ;;3
esac
exit 04
  1. 1matcher が見るのは道具の名前。中身で絞る if 欄は確実ではないので、止める判断はフックの中で見る。
  2. 2実行されようとしている引数が、標準入力に JSON で届く。
  3. 32 で終えると止まり、標準エラーの文が Claude に届く。Claude はそれを読んで、別の進め方を考える。
  4. 40 は「許可」ではなく「意見なし」。いつもの規則とモードの判定に戻る。

ポイント止めるのは、フックの exit 2（または拒否の判定）。止めるフックは allow の規則より強く、プロンプトの頼みごとと違って、動けば確実に効く。

※ 2 以外で終わる・スクリプトが無い・時間切れのときは、止めずに素通しになります。本当に止まるかを試しておきます。

フックと権限の規則

ゴールフックの判定と権限の規則が重なったとき、どちらが効くかを言える。

フック規則結果
denyallow止まる。止めるフックが、allow の規則に勝つ
allowdeny止まる。deny の規則は、フックが許しても外れない
意見なし─いつもの規則とモードで決まる

コマンドの文字列の照合は、書き方を変えるとすり抜けられることがあります。フックは、deny の規則やサンドボックスと重ねて使います（〈守りを重ねる〉）。

フック自体の危うさ

ゴールフックを動かすときに気をつけることを言える。

フックは、自分の権限で任意のコマンドを動かします。見知らぬリポジトリの .claude/settings.json に書かれたフックは、対話なしの実行（-p）や Agent SDK では、信頼の確認なしに動きます。CI ではフックや CLAUDE.md などを読まない実行（--bare）を使うか、リポジトリの設定を確かめてから動かします（〈Claude Code の動かし方〉）。

誤解「フックは Claude が判断して呼ぶので、Claude が言いくるめられると止まらない」 実際はフックを呼ぶのは Claude Code（アプリ）。Claude がどう判断しても、止めると決めた呼び出しは止まる。
