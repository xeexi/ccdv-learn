7-3　守りを重ねる ─ ガードレールと最小権限

ゴール内容の方針・守りの重ね方・最小権限を組み合わせて設計できる。

どの守りも、1つだけでは破られることがあります。入力・指示・権限・出力・人の確認と層を重ね、どれかが抜けても次の層で止まるようにします。

DOMAIN 7Guardrails and Safe Deployment

層止めるもの例
入力危ない依頼を、本筋に届く前に軽いモデルでの事前の検査
指示決まりから外れた振る舞いをsystem の方針と断り方
権限できてはいけない操作を要る道具だけ・deny の規則・サンドボックス
出力漏れや誤りを、出す前に出力の検査・後処理
人取り返しのつかない操作を実行前の承認

ポイント守りは重ねる。頼む層（指示）は確率で破られるので、強制する層（権限・検査・承認）と組にする。

内容の方針

ゴールアプリが守る内容の方針が、どこから来て、どう効かせるかを言える。

Claude を使うアプリは、Anthropic の使用ポリシーを守ります。利用者と話すチャットボットやエージェントは、高リスクの用途でなくても、相手が AI だと開示します（少なくとも会話の頭で）。高リスクの用途では、その分野の資格を持つ人が出す前に確かめる仕組みも求められます。その上に、アプリ自身の方針（扱う話題・断るもの）を決め、system と入力・出力の検査で効かせます。

設計の最初から、プライバシー（要らない個人情報を集めない・残さない）と、誰に何を許すか（ID と権限の管理）を組み込みます。後から足す守りは、抜けやすくなります。

最小権限

ゴールClaude と人に渡す権限を、要る分だけに絞れる。

権限は、仕事に要る分だけを渡します。これが最小権限（least privilege）の考え方で、破られたときの被害の大きさを、渡した権限の範囲に閉じ込めます。

手中身
道具仕事に要る道具だけを渡す。読むだけで足りるなら、書き込む道具は渡さない
規則deny・ask・allow の規則で、道具と引数を絞る。規則は Claude ではなく Claude Code が強制する
隔離サンドボックスで、ファイルとネットワークの届く範囲を閉じる。インジェクションで Claude の判断が破られても効く。効くのはシェルのコマンドとその子のプロセスで、ファイルを読む・編集する道具や Web の取得は権限の規則で守るので、両方を組む
人の役割人にも要る役割だけを与える（使うだけ・鍵を作れる・設定を変えられる、など）
誤解「system プロンプトで禁止しておけば、道具の権限は広くてもよい」 実際は指示は確率で破られる。できることそのものを権限で絞っておけば、破られても被害は限られる。
