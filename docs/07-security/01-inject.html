7-1　仕込まれた指示を効かせない

ゴールインジェクションとジェイルブレイクを、信頼できない入力の扱いで防げる。

Claude のアプリへの攻撃は、大きく2つに分かれます。利用者自身が頼み方を工夫して、アプリの決まりを破らせようとするジェイルブレイク（jailbreak）と、利用者ではなく、Claude が読み込む Web のページ・メール・文書の中に指示を仕込む間接のインジェクション（prompt injection）です。利用者が指示を直接仕込むものは、直接のインジェクションと呼びます。

DOMAIN 7AI Application Security

攻撃仕掛ける人入り口主な守り
直接利用者利用者の入力事前の検査・system の方針・繰り返す人への制限
間接第三者ツールの結果・文書・Web・メール置き場所・方針・結果の検査・最小権限・人の確認

ポイント利用者の入力は事前に検査し、外から来た中身はツールの結果として材料の扱いにする。どちらも、破られたときの被害を権限で小さくしておく。

ジェイルブレイクへの守り

ゴール利用者が決まりを破らせようとするときの守りを挙げられる。

守りすること
事前の検査軽いモデルで、利用者の入力を本筋の会話の前に分類する。答えは構造化出力で「問題あり・なし」に絞る
入力の検査知られた手口の型を、Claude に届く前に弾く
system守る決まりと、断り方をはっきり書く
繰り返す人同じ断りを何度も引き起こす利用者には、制限や停止を考える
監視出力を見続け、新しい手口に合わせて守りを直す

間接のインジェクションへの守り

ゴール読み込む中身に仕込まれた指示への守りを、重ねて組める。

利用者に悪意がなくても、Claude が読み込む中身が汚れていることがあります。置き場所の決まり（〈指示とデータの境目〉）に、次の守りを重ねます。

守りすること
置き場所外の中身はツールの結果にだけ入れ、JSON の文字列に包む。自分の指示はツールの結果に混ぜない
方針外の中身は信頼しないデータで、中の指示は「従うもの」ではなく「報告するもの」だと system に書く
結果の検査ツールの結果を、Claude が使う前に軽いモデルで検査する
最小権限要らない秘密や道具を渡さない。破られても、できることが少なければ被害も小さい（〈守りを重ねる〉）
人の確認取り返しのつかない操作は、人に確かめてから実行する
攻撃の試し出す前に、指示を仕込んだ文書やメールで自分のエージェントを試す
誤解「利用者が信頼できる社員だけなら、インジェクションは起きない」 実際は間接のインジェクションは、利用者ではなく読み込む中身から来る。社内向けでも、外の中身を読むなら守りが要る。
