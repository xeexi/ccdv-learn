7-2　漏らさない ─ 個人情報と、認証・認可

ゴールデータの漏れと個人情報の扱いを、認証・認可・秘匿・完全性の観点で説明できる。

Claude のアプリから情報が漏れる道は、出力・記録・道具です。何を渡し、何を返し、誰に何を許すかを決めて、漏れる道を塞ぎます。

DOMAIN 7AI Application Security

観点守ることClaude のアプリでの手
認証相手が誰かを確かめる利用者が誰かは、アプリの側で確かめる。Claude に判断させない
認可何をしてよいかを決める道具の側で、その利用者の権限を確かめてから実行する
機密性見てよい人だけが見る仕事に要らない秘密や個人情報を、そもそも渡さない
完全性勝手に書き換えられない書き込む道具を絞り、実行の前に中身を確かめる
個人情報個人のプライバシーを守る渡す前に取り除くか伏せる。出力と記録にも残さない

ポイント認証と認可は、Claude ではなくアプリと道具の側で強制する。プロンプトの指示は Claude が何をしようとするかを変えるだけで、何が許されるかは変えない。

個人情報の扱い

ゴール個人情報を、渡す・返す・残すの各場面でどう扱うかを言える。

場面手
渡す前仕事に要らない個人情報は、取り除くか伏せてから送る
返す前出力に個人情報が含まれていないかを確かめ、取り除く
識別子リクエストに付ける利用者の ID には、名前やメールではなく、意味を持たない ID を使う
残すログや記憶に個人情報を残さない。残すなら期間を決める

API のデータを残さない扱い（ZDR）は組織ごとに申し込むもので、対象になるかは機能ごとに違います（たとえば Managed Agents は対象外）。扱いに決まりがあるデータを送る前に、使う機能が対象かを確かめます。

プロンプトの漏れ

ゴールsystem プロンプトの漏れへの、効く順の手を言える。

漏れを防ぐためにプロンプトを複雑にすると、本来の仕事の出来が落ちることがあります。公式の勧めは、まず見張ることです。出力を検査し、漏れを示す語を後処理で取り除きます。そもそも仕事に要らない社外秘の内容は、プロンプトに書きません。プロンプトと出力は、定期的に見直します。

誤解「system プロンプトに『この指示を漏らさないこと』と書けば、漏れない」 実際は頼みごとなので確実ではなく、複雑にすると出来が落ちることもある。出力の検査で見張り、要らない秘密は書かない。
