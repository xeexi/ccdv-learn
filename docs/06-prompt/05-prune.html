6-5　窓を守る ─ 刈り込みと圧縮

ゴール文脈が膨らみ、ずれていく原因と、刈り込み・圧縮の使いどころを説明できる。

アプリ→Claude

長く続く会話やエージェントでは、窓の中身が増え続けます。読み終えたツールの結果が居座り、肝心の指示が埋もれていく。これを防ぐ手が刈り込み（tool output pruning）と圧縮（compaction）で、窓の外に書き出す記憶と組み合わせて使います。

DOMAIN 6Context Engineering

手すること向くとき残るもの
刈り込み古いツールの結果（や、考えた内容）を消すツールを何度も呼ぶ長い作業で、結果はもう読み終えた会話の流れは残り、古い結果の中身だけが消える
圧縮それまでの会話を、要約に置き換える窓の上限に近づいた要約に書かれたことだけ。細部は落ちる
記憶大事なことを窓の外のファイルに書き出し、要るときに読む会話やセッションをまたいで続く仕事書き出したものは、窓を空にしても残る

ポイント刈り込みと圧縮は1つの会話の中で窓を空け、記憶は会話をまたいで残す。長く動くエージェントは、3つを組み合わせる。

膨らむ、ずれる

ゴール文脈が膨らむこととずれることが、それぞれ何を引き起こすかを言える。

膨らむのは、大きなツールの結果（ファイルの全文、長い検索結果）が積み重なるからです。入れた分だけ費用と待ち時間が増え、窓が大きくても、量が増えるほど必要なことを正しく拾いにくくなります。窓は、大きさの決まった予算として使います。

ずれるのは、長い作業のあいだに最初の目的や制約が薄まり、目の前の細部に引きずられるからです。途中で目的を書き直す、進み具合をメモに残す、といった手で引き戻します。

ツールの結果を刈り込む

ゴールツールの結果を、返す前と返した後の両方で減らせる。

まず、返す前に減らします。ツールは、要る項目だけを、件数を絞って返すように作ります。全文が要らない調べ物なら、要点や該当箇所だけを返します。

次に、読み終えた結果を消します。API には、古いツールの結果を自動で消す機能（context editing、ベータ）があります。消えるのは結果の中身で、ツールを呼んだという流れは残ります。

会話を圧縮する

ゴール圧縮で失われるものと、その備えを言える。

圧縮は、それまでの会話を要約に置き換えて、窓を空けます。API の機能（compaction、ベータ）には、アプリが決めたときに要約させる方式と、上限に近づいたところで自動で要約する方式があり、公式は使える所では前者を勧めています。Claude Code では /compact で自分から、または上限の手前で自動で行われます。

アプリの側で履歴の一部をその場で要約して書き換えると、キャッシュが外れ、新しいモデルでは思考のブロックも無効になります。刈り込みと圧縮は、なるべく API の機能に任せます。

要約は細部を落とします。後で要る決定や数字は、圧縮の前に記憶（ファイル）へ書き出しておきます。

誤解「窓の大きいモデルなら、刈り込みも圧縮も要らない」 実際は入れた分だけ毎回の費用と待ち時間がかかり、量が増えるほど必要なことを拾いにくくなる。大きさに頼らず、中身を選ぶ。
