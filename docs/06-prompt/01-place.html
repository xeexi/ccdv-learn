6-1　指示は system に、材料は user に

ゴール指示と材料をどこに置くかで、効き方がどう変わるかを説明できる。

アプリ→Claude

同じ文でも、どこに置くかで扱いが変わります。system はアプリを運営する側の声、user は利用者の声、ツールの結果は外から届いたデータとして読まれます。

DOMAIN 6Prompt Engineering

置き場所誰の声として読まれるか置くもの
systemアプリを運営する側役割、最初から効かせたい指示、方針（ツールの結果はデータとして扱う、など）
user利用者今回の依頼、利用者が渡した資料、質問
ツール結果外から届いたデータツールが返した内容。外から届いた信頼できない中身（受信したメール・Web の文など）は、ここに入れる
ツール説明道具の説明書いつ使うか、引数の意味

ポイント役割と方針は system、今回の依頼と資料は user。外から来た中身には、指示の権限を与えない。

system に置くもの

ゴール役割と方針を system に置く理由を言える。

system に役割を1文書くだけでも、振る舞いと口調が定まります。会話の最初から最後まで効かせたい方針も、ここに置きます。運営する側の指示と利用者の依頼がぶつかったときは、運営する側の指示が優先されます。

途中から効かせたい指示を足すために system の本文を書き換えると、system から後ろのキャッシュが外れます。新しいモデルでは、それより後の思考のブロックも無効になり、送るとエラーになることがあります。対応するモデルでは、会話の途中に system のメッセージを足す形を使えば、それまでの部分を使い回せます。履歴は前の回を書き換えず、後ろに足すだけにするのが、公式の勧める形です。

誤解「外から取ってきた文章も system に入れれば、確実に読ませられる」 実際はsystem に入れると、その文章に運営する側の権限を与えてしまう。信頼できない中身は、ツールの結果に入れて、データとして扱わせる。

長い資料は先頭に、質問は最後に

ゴール長い資料と質問の並べ方を決められる。

長い資料を渡すときは、資料をプロンプトの先頭に、質問や指示を最後に置きます。質問を最後に置くと、応答の質が上がります。資料が複数なら、1つずつタグで区切って出どころを添え、答える前に関係する箇所を抜き出させます。

部品ごとの置き場所

ゴールアプリを作る部品ごとに、どの指示をどこに置くかを選べる。

Claude を使うアプリでは、指示は1か所ではなく部品に分かれて入ります。道具をいつ使うかはツールの説明に、方針は system に、今回の依頼は user に書きます。自分の指示を、ツールの結果の中に混ぜないのも決まりです。結果の中の指示は、Claude がデータとして疑ってかかるからです。

Claude Code なら、いつも効かせる約束は CLAUDE.md に、必要なときだけの手順は Skills に置きます（〈Claude Code の部品〉）。
