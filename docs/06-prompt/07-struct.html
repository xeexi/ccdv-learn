6-7　出力を形で受け取り、確かめる

ゴール構造化出力・検証・壊れた出力への備えを組み合わせて、受け取り側を作れる。

Claude→アプリ

返ってきた出力をプログラムで使うなら、形を決めて受け取ります。形は API に保証させ、中身が正しいかはアプリで確かめます。

DOMAIN 6Output Handling

JSON の形を指定する

"output_config": {
  "format": {
    "type": "json_schema",1
    "schema": {
      "type": "object",
      "properties": {
        "category": { "type": "string",
          "enum": ["請求", "配送", "その他"] },
        "summary": { "type": "string" } },
      "required": ["category", "summary"],
      "additionalProperties": false } } }2
  1. 1応答の本文を、この JSON Schema の形に縛る。
  2. 2余計な項目を許さない指定が要る。数値の範囲や文字数のような制約は、この指定の中では使えない。
縛るもの指定保証されること
応答の本文output_config.format指定した JSON Schema の形で返る
ツール引数ツールの定義に strict: true引数が、定義した入力の形になる

ポイント形は API の指定で保証する。ただし保証されるのは形だけで、中身の正しさまでは保証しない。

形が正しくても、中身は確かめる

ゴール形の保証のあとに、アプリで確かめることを挙げられる。

形の指定では書けない条件（値の範囲、項目どうしの矛盾、実在する番号か）は、受け取った側で確かめます。SDK には、受け取った出力を型に照らして確かめる仕組み（messages.parse()）もあります。

確かめて駄目だったら、どこがどう駄目かを添えて、もう一度頼みます。元の入力・前回の出力・見つかった誤りを渡すと、直してもらいやすくなります。

壊れた出力に備える

ゴール出力を読む前に確かめることと、読み方の注意を言える。

形の保証があっても、途中で止まった応答は形どおりになりません。出力を読む前に、応答の stop_reason を確かめます。

止まった理由起きていること
max_tokens上限で打ち切られていて、JSON が途中で終わっていることがある
refusal安全のために断っていて、形どおりの出力になっていないことがある
model_context_window_exceeded書く途中で窓の端に届いて、JSON が途中で終わっていることがある

JSON は必ずパーサで読みます。文字列の照合や正規表現で拾うと、書き方の小さな違いで壊れます。形の保証にも1つ例外があり、enum の値は大文字小文字だけが違う形で返ることがあります。英字の値は大文字小文字を区別せずに比べ、大文字小文字だけで違う値は作りません。

※ 応答の書き出しをこちらで先に埋めて形を誘導する方法（prefill）は、新しいモデルでは受け付けられません。形を決めたいときは、構造化出力を使います。
