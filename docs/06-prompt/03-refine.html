6-3　直しながら寄せる・入力を整える

ゴール結果を見てプロンプトを直す手順と、入力を整えてから渡す理由を説明できる。

最初のプロンプトで完成することは、まずありません。何をもって成功とするかを先に決め、確かめながら直していきます。

DOMAIN 6Prompt Engineering

失敗の見え方から、直す場所を選ぶ

ゴール見えた失敗から、プロンプトのどこを直すかを選べる。

見えた失敗直す場所
形の崩れ出力の形をはっきり書く。例を見せる。プログラムで読むなら構造化出力
判断の揺れ判断の基準と理由を書く。迷いやすい例を、例として見せる
やりすぎ頼んでいないことまでする。してほしい範囲を、はっきり書く
効きすぎ不要な場面でも従おうとする。強い口調を和らげ、細かすぎる手順を減らす

難しい出力は、下書き → 基準に照らした見直し → 手直し、と別々の呼び出しに分けると、それぞれを確かめながら直せます。

入力を整えてから渡す

ゴール利用者の入力や外から取った中身を、プロンプトに入れる前に整える理由と方法を言える。

利用者の入力や、Web・メール・ファイルから取ってきた中身には、指示に見える文が混じることがあります。そのまま指示の続きにつなげると、Claude はどこまでが指示で、どこからが材料かを見分けられません。

整え方中身
区切る材料はタグで囲むか、ツールの結果として渡す。system には入れない
包む信頼できない中身は JSON の文字列にして渡す。中にタグや引用符があっても、材料の外に抜け出せない
添える「知らない送り主からのメールの本文」のように、何がどこから来たかを書き添える
決める材料の中の指示には従わないことを、system で決めておく

入力を整えるのは、答えの質のためだけでなく、仕込まれた指示から守るためでもあります（〈仕込まれた指示を効かせない〉）。

ポイント直すときは基準とテストを先に決め、1か所ずつ比べる。外から来た中身は、区切って、データとして渡す。
