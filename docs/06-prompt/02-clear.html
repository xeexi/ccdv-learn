6-2　はっきり頼む ─ 基準・制約・例

ゴールあいまいな指示を、基準・出力の制約・例で直せる。

Claude は、優秀でも事情を知らない新しい同僚のように指示を読みます。前提を知らない人が読んで迷う指示なら、Claude も迷います。

DOMAIN 6Prompt Engineering

あいまい

この問い合わせを分類して。

はっきり

<instructions>
問い合わせを「請求」「配送」「その他」の1つに分類する。1
複数に当たるときは、利用者が最初に困っていることで決める。2
答えは、カテゴリ名だけを書く。3
</instructions>
<inquiry>（問い合わせの本文）</inquiry>4
  1. 1何をするかと、選べるものをはっきり書く。
  2. 2迷う場合の決め方（判断の基準）を書く。
  3. 3出力の形と長さを決める。
  4. 4指示と材料を、タグで分ける。材料の中の文を、指示と取り違えさせない。

ポイント何を・どんな基準で・どんな形で、の3つを書き、指示と材料をタグで分ける。

理由を添え、してほしいことを書く

ゴール禁止の羅列より、理由と望む形を書くほうが効く理由を言える。

指示には理由を添えます。「省略記号を使わない」だけより「音声で読み上げるので、省略記号を使わない」のほうが、Claude は似た場面にも正しく広げられます。「〜しないで」を並べるより、代わりにどうしてほしいかを書きます。

「絶対に」「必ず」のような強い口調は、新しいモデルでは効きすぎて、不要な場面でも従おうとすることがあります。古いモデル向けに書いた細かすぎる手順も、かえって出来を下げることがあります。

例を見せる

ゴールよい例の条件を言える。

条件中身
数3〜5個が目安（公式の推奨）
関係がある実際の入力に近い例にする
互いに違う端の場合も含め、意図しない特徴まで真似されないよう、ばらつかせる
区切る例は <example> のようなタグで囲み、指示と分ける

※ 例の数と費用の関係は〈例を何個見せるか〉で扱いました。

出力の制約

ゴール出力の形と長さを決める方法を選べる。

出力の形は、言葉で指定するか、タグで囲ませるか、プログラムで読むなら構造化出力で縛ります（〈出力を形で受け取り、確かめる〉）。長さや書き方も、望む形をそのまま書きます。

プロンプトの書き方は、出力に移ります。プロンプトを見出しや箇条書きだらけにすると、出力もそうなりやすくなります。
