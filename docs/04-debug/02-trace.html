4-2　どこで壊れたかを切り分ける

ゴールトレースから、繋ぎ込み側の不具合かモデルの出力の問題かを切り分けられる。

エージェントがおかしな答えを返したとき、原因は大きく2か所にあります。アプリの繋ぎ込み（送った中身・道具・データ）か、モデルの出力そのものかです。1周ごとの記録（トレース）を並べれば、どちらかを切り分けられます。

DOMAIN 4Debugging and Error Handling

見えたこと中身疑う場所
道具の失敗道具の結果が空か、エラーになっている繋ぎ込み（道具・データ）
資料の抜け送った履歴に、要る資料が無いか古い繋ぎ込み（組み立て）
JSON 切れ出力の JSON が途中で終わっているstop_reason と出力の上限
答えの誤り入力は正しいのに、答えが違うモデルの出力（プロンプト・形・区分）
答えの揺れ同じ入力で、答えが回ごとに違う非決定性。判定の仕方を見直す

ポイントまず繋ぎ込み（入力・道具・データ）を記録で確かめ、それが正しいと分かってから、モデルの出力を疑う。

記録を取る手段

ゴールClaude Code・Agent SDK・Managed Agents で、1周ごとの記録を見る手段を言える。

手段見えること
--verboseClaude Code の、1周ごとの全部の出力
--debugMCP の接続やフックなどを含む、詳しい動きの記録
--safe-modeCLAUDE.md・Skills・フック・MCP などを全部外して起動し、設定が原因かを比べる
Agent SDK流れてくるメッセージと、最後の結果の種類（上限で止まったか、など）。OpenTelemetry にも書き出せる
Managed AgentsConsole のセッションの画面で、イベントの履歴と道具の結果を見る

Claude Code で設定した指示や機能が効かないときは、たいていファイルが読み込まれていないか、別の場所から読まれているか、別のファイルに上書きされています。/context で、このセッションに実際に読み込まれた CLAUDE.md と rules を確かめ、--safe-mode と比べます（/memory は置き場所ごとのファイルを一覧して開く手で、読み込まれたかは分かりません）。

誤解「おかしな答えが出たら、まずプロンプトを書き足して直す」 実際は原因が道具の失敗や資料の抜けなら、プロンプトをいくら直しても治らない。記録で入力と道具の結果を先に確かめる。
