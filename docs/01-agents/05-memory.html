1-5　長く動かす ─ 記憶・窓・子

ゴール長い仕事で文脈を保つ3つの手を選び分けられる。

何時間も続く仕事は、1つの窓には収まりません。長く動くエージェントは、窓の中身を入れ替えながら進みます。そのための手は3つで、どれを主に使うかは仕事の形で決めます。

DOMAIN 1Agent Patterns and Frameworks

手すること向く仕事
圧縮古い会話を要約に置き換えて、窓を空けるやり取りを重ねながら、会話の流れを保ちたい仕事
メモ進み具合や決めたことを窓の外のファイルに書き、要るときに読み戻す区切りのはっきりした段階を、繰り返し積み上げる仕事
子調べ物を子の窓で済ませ、要点だけを受け取る並べて調べると得になる、複雑な調査や分析

ポイント窓は、大きくても使えば尽きる。長い仕事では、窓に何を残すかを、3つの手を組み合わせて決め続ける。

※ 圧縮と刈り込みの仕組みは〈窓を守る〉、子への渡し方は〈文脈を分ける〉で扱いました。

記憶のツール ─ 窓の外にメモを残す

ゴールmemory ツールの動き方と、アプリが負う責任を言える。

API には、窓の外にメモを残すための道具（memory ツール）があります。Claude は仕事を始める前にメモを確かめ、分かったことを /memories の下のファイルに書き、後の会話で読み戻して続きをします。

この道具はクライアント側で動きます。Claude が頼むのはファイルの操作（見る・作る・書き換える・消す など）だけで、実際に保存するのはアプリです。保存先も、アプリが決めます。

アプリの責任中身
場所を守る/memories の外を指すパス（../ を含むものなど）を、必ず拒む
中身を守る秘密の情報が書かれないよう、書く前に確かめる
大きさファイルの大きさに上限を設け、長く使われないメモは消す

記憶は、圧縮と組み合わせて使います。圧縮で窓を小さく保ちながら、要約で消えては困ることを記憶に残す形です。

必要になってから読む

ゴール資料を先に全部入れず、要るときに読ませる理由を言える。

関係しそうな資料を最初に全部窓に入れるより、ファイルの場所や検索の条件のような手がかりだけを持たせ、要るときに道具で読ませるほうが窓を守れます。Claude Code は、決まりごとを書いた CLAUDE.md は最初に読み込み、コードは検索の道具で、要る分だけを探して読みます。

誤解「記憶やメモに書いたことは、Claude が必ず守る」 実際は記憶は、文脈として読まれるだけで強制力はない。毎回必ず守らせたいことは、コードの仕組みに置く（〈決まった処理はフックで〉）。
