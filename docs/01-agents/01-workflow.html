1-1　ワークフローか、エージェントか

ゴール手順が決まっている仕事と決まっていない仕事で、組み方を選び分けられる。

Claude に仕事をさせる組み方は、大きく2つに分かれます。手順をコードで決めておくワークフローと、手順を Claude がその場で決めるエージェントです。どちらも Claude と道具を組み合わせて使い、違うのは次に何をするかを誰が決めるかです。

DOMAIN 1Agent Architecture

比べる点ワークフローエージェント
次の手コードが決める。決めておいた道筋のとおりに、Claude と道具を呼ぶClaude が決める。結果を見ながら、使う道具と進め方を選ぶ
向く仕事手順が決まっている仕事（毎月の請求書の処理など）何手かかるか読めず、道筋を決めておけない仕事（原因の分からない不具合の調査など）
得動きを予測でき、結果がそろう途中で分かったことに合わせて、進め方を変えられる
代償決めておいた道筋にない仕事には対応できない費用と待ち時間が増える。結果がぶれ、誤りが積み重なることもある

ポイント分かれ目は「手順を先に決めておけるか」。決めておけるならワークフロー、決めておけないときだけエージェントにする。

まず、いちばん単純な形から

ゴール1回の呼び出しで足りるかを、先に確かめる理由を言える。

公式の勧めは、いちばん単純な形から始め、足りないと分かったときだけ複雑にすることです。多くの用途は、検索で集めた資料と例を添えた1回の呼び出しで足ります。複雑にするかどうかは、評価して出来が上がると確かめてから決めます。

ワークフローの5つの型

ゴール仕事の形から、ワークフローの型を選べる。

型すること向く仕事
順につなぐ
prompt chaining		前の呼び出しの出力を、次の呼び出しに渡す。途中にコードの関門を置ける決まった小さな仕事に、きれいに分けられる
振り分ける
routing		入力を分類し、種類ごとの処理へ送る種類ごとに扱いを変えたほうがよく、分類を正確にできる
並べる
parallelization		仕事を分担して同時に進めるか、同じ仕事を何回かさせて比べる速さが要る。または確かさのために、複数の見方が要る
割り振る
orchestrator-workers		監督役が入力を見て、その場で仕事を割り、結果をまとめる要る小さな仕事を、先に読めない（〈監督役と子〉）
評価で直す
evaluator-optimizer		1つが書き、もう1つが評価して、直させる評価の基準がはっきりしていて、直すほど良くなる

エージェントにするときの備え

ゴールエージェントを選んだときに要る備えを挙げられる。

エージェントにするのは、Claude の判断をある程度信頼して任せるということです。自分で進むぶん費用が増え、誤りが積み重なるおそれもあるので、次の備えと組み合わせます。

備え中身
確かめる各段階で、道具の結果やコードの実行結果のような実際の結果を返し、進み具合を確かめさせる
止める反復の上限のような、止める条件をコードに置く
人に戻す区切りや、行き詰まったところで、人の判断を仰ぐ
試す本番の前に、隔離した環境（サンドボックス）で十分に試す
誤解「エージェントのほうが賢いので、どんな仕事もエージェントにしたほうがよい」 実際は手順が決まっている仕事に柔軟さは要らない。エージェントにすると、費用と待ち時間と、結果のばらつきを払うだけになる。
