1-11　決まった処理はフックで

ゴール毎回必ず行う処理を、プロンプトではなくフックに置く理由を説明できる。

Claude→フック→ツール

CLAUDE.md やプロンプトに書いた指示は、頼みごとです。多くの場合は守られても、必ずではありません。毎回かならず行う処理は、フックに置きます。フックは、決まった時点で自分のコードを必ず動かす、決定的（deterministic）な仕組みです。

DOMAIN 1Agent Construction with Claude

編集のたびに整形する（.claude/settings.json）

{ "hooks": {
  "PostToolUse": [{1
    "matcher": "Edit|Write",2
    "hooks": [{ "type": "command",
      "command": ".claude/hooks/format.sh" }]3
  }] } }
  1. 1いつ動かすか。道具が動いた後（PostToolUse）。
  2. 2どの道具のときか。ファイルを編集・作成したときだけ。
  3. 3何を動かすか。道具の名前と引数が JSON で渡るので、編集されたファイルを整形する。

ポイントプロンプトは確率で守られる頼みごと、フックは必ず動くコード。整形・検査・記録・禁止のように、毎回そうでなければ困ることはフックに置く。

どの時点で動かすか

ゴール主なイベントと、その使いどころを言える。

イベント動く時点使いどころ
SessionStart始まったとき・再開したとき最新の状態や決まりごとを、文脈に足す
UserPromptSubmit利用者の入力を受けたとき入力を確かめる。要る情報を足す
PreToolUse道具が動く前止める。引数を書き換える
PostToolUse道具が動いた後整形・検査・記録
Stop答え終えようとしたとき条件を満たすまで、終わらせずに続けさせる

ほかにも、子が終わったとき（SubagentStop）や、圧縮の前（PreCompact）などに掛けられます。

止めるときは、終了コード 2

ゴールフックが処理を止める仕組みを言える。

コマンドのフックは、終了コードで結果を伝えます。0 は成功、2 は「止める」です。PreToolUse で 2 を返すと道具は実行されず、標準エラーに書いた理由が Claude に渡ります。Claude はそれを読んで、別の進め方を考えます。

2 以外の失敗（1 など）では止まりません。規則を守らせるためのフックは、2 で終えます。JSON を返せば、許可・拒否・人に確認の判定や、引数の書き換えもできます。

Agent SDK では関数で書く

ゴールAgent SDK でフックを書く形を言える。

Agent SDK でも、同じイベントにフックを掛けられます。こちらは自分のコードの中の関数で、呼び出しの情報（道具の名前・引数など）を受け取り、許可・拒否・入力の書き換え・文脈の追加を返します。設定ファイルに書いたコマンドのフックも読み込まれます。

誤解「CLAUDE.md に『編集したら必ず整形する』と書けば、毎回整形される」 実際は頼みごとなので、抜けることがある。毎回必ずなら、編集の後に動くフックに置く。

※ 壊す操作を確実に止める使い方は〈壊す操作はフックで止める〉で扱います。
