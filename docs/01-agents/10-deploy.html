1-10　どこで動かすか ─ 自前か、Anthropic が動かすか

ゴール自前で動かす形と Anthropic が動かす形を、管理の手間と制約で選び分けられる。

エージェントを動かすときに決めることは2つあります。ループ（ハーネス）を誰が回すかと、道具を実行する場所を誰が持つかです。この2つは、別々に選べます。

DOMAIN 1Agent Construction with Claude

ポイントループをどこで回すかと、道具をどこで実行するかは、別の軸。

Managed Agents の部品

ゴールManaged Agents を使うときに作るものを言える。

部品中身
Agentモデル・system・道具・MCP・Skills の組。一度作り、ID で使い回す
Environmentどこで動かすか。Anthropic のクラウドのサンドボックスか、自前のサンドボックスか
Session1つの仕事を進める、動いているエージェント。会話とファイルはサーバ側に残る
Eventsアプリとエージェントのやり取り。指示を送り、進み具合を SSE で受け取る

選び方

ゴール仕事の性質と制約から、動かす形を選べる。

形向くとき
全部任せる数分から数時間かかる仕事や、非同期の仕事。ループ・サンドボックス・道具の実行の層を、自分で作りたくない
実行は手元外に出せないデータや、社内のネットワークにしか無いサービスを使う。自社の監査の下で動かしたい
全部自前ループそのものを自分の基盤で動かす必要がある。1周ごとの動きを細かく決めたい

Managed Agents は、会話やファイルをサーバ側に保存する作りです。データを残さない扱い（ZDR）などの対象になるかは機能ごとに違うので、データの扱いに決まりがある仕事では、選ぶ前に確かめます。

誤解「自前のサンドボックスを選べば、データは Anthropic に一切渡らない」 実際は道具の実行とファイルは手元に残るが、道具の入力と結果は、Claude が読むために Anthropic 側へ送られる。

自前で動かすときに要るもの

ゴールAgent SDK を自前で動かすときの前提を言える。

Agent SDK は、裏で Claude Code の本体を別のプロセスとして起動し、そのプロセスがシェル・作業ディレクトリ・セッションのファイルを持ちます。状態を持たない API の中継とは違い、動いているエージェントの数だけ、ファイルとプロセスを抱えた環境が要ります。

ふつうはコンテナで隔離し、仕事1つごとにコンテナを作って捨てる形か、コンテナを置いたまま仕事を受け続ける形を選びます。
