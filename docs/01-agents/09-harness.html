1-9　自前のループとハーネス

ゴールループを自分で書くときに要る部品と、SDK を使わない理由を説明できる。

Claude を呼び、Claude が頼んだ道具を実行先へ振り分けるループを、ハーネスと呼びます。自分で書けば1周ごとの動きをすべて決められますが、SDK が肩代わりしていた部品を、自分で用意することになります。

DOMAIN 1Agent Construction with Claude

部品役目
振り分け道具の名前から関数を選んで実行し、結果を返す（〈実行するのはアプリ〉）
関門取り返しのつかない操作の前に、承認を挟む（〈失敗の返し方と、承認の挟み方〉）
失敗道具の失敗を、is_error と説明の文で返す
止める反復や費用の上限を置く（〈ループの1周〉）
窓古い結果の刈り込みや圧縮で、窓を守る（〈窓を守る〉）
記録送ったもの・返ったもの・道具の結果を残し、後から追えるようにする
実行場所道具を、隔離した環境（サンドボックス）で動かす

ポイントハーネスは、Claude を呼ぶループと、その周りの部品の集まり。自前で書くなら、どの部品も自分の責任になる。

3つの作り方

ゴール手書きのループ・tool runner・Agent SDK を選び分けられる。

作り方自分で書くもの向くとき
手書きループ全体と、すべての部品1周ごとに、承認・記録・条件つきの実行を細かく決めたい
tool runner道具の関数。ループと失敗の包みは SDK が持ち、回数の上限も指定できる（いまはベータ）自分の道具を、手早くループで回したい
Agent SDK許す道具と上限の設定Claude Code と同じ道具とループを、そのまま使いたい

自前で書く理由

ゴールSDK を使わずに自前で書く理由を挙げられる。

自前で書くのは、用意された部品では足りないか、合わないときです。自分の実行環境と独自の道具だけを使いたい、Claude Code の道具は要らない、1周ごとの承認・記録・再試行を細かく決めたい、今あるシステムの中にループを組み込みたい、といった場合です。

そうした理由が無いなら、用意された部品を使うほうが安全です。自前のハーネスは、すべての部品を自分で保守し続けることになります。

誤解「ループを自前で書けば、そのぶん速く、安くなる」 実際は送る中身が同じなら、費用は変わらない。増えるのは、自分で保守する部品のほう。
