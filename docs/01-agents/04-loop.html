1-4　ループの1周 ─ ツールを使い続ける

ゴールツールを使うループの1周と、止まる条件を説明できる。

アプリ→Claude→アプリ

エージェントの中身は、多くの場合とても単純です。Claude が道具を頼んだら、実行して結果を返す。これを、Claude が道具を頼まなくなるまで繰り返します。この繰り返しがツールを使うループ（tool-use loops）です。

DOMAIN 1Agent Patterns and Frameworks

ループの骨組み（Python）

while True:
    res = client.messages.create(
        model=MODEL, max_tokens=1024,
        tools=tools, messages=msgs)1
    msgs.append({"role": "assistant",
        "content": res.content})2
    if res.stop_reason != "tool_use":
        break3
    results = run_tools(res.content)
    msgs.append({"role": "user",
        "content": results})4
  1. 1毎回、ここまでの履歴（msgs）を全部送る。道具の定義も毎回渡す。
  2. 2応答は、道具の依頼（tool_use）ごと丸ごと履歴に足す。
  3. 3道具を頼まなかったら、ループを抜ける。止まった理由は stop_reason で見る。
  4. 4頼まれた道具をすべて実行し、結果（tool_result）を1つのメッセージにまとめて返す。run_tools は自分で書く関数（〈実行するのはアプリ〉）。

ポイントループを回しているのは、アプリの while 文。続けるか止めるかは stop_reason で決め、Claude の返事の文面では決めない。

止まる条件

ゴールstop_reason の値ごとに、アプリがすることを言える。

値意味アプリがすること
tool_use道具を頼んだ実行して結果を返し、ループを続ける
end_turn言い終えた完了として、答えを使う
max_tokens出力の上限で切れたそのまま使わない。上限を見直すか、続きを頼む
refusal安全のために断った完了として扱わず、別の経路へ回す
pause_turnサーバ側の道具の途中で区切った応答をそのまま足して、送り直す

止める条件は、もう1つコードに置きます。反復の上限です。正常な終わりは end_turn で、上限は、壊れたときに回り続けないための保険です。上限に達したら、そこまでの結果を人に戻します。

確かめられる仕事ほど、回して良くなる

ゴールループで出来が上がる仕事の条件と、そのために渡すものを言える。

ループの中で Claude が進み具合を知る手がかりは、返ってくる道具の結果だけです。公式も、各段階で道具の結果やコードの実行結果のような実際の結果を得て、進み具合を確かめさせることを勧めています。

だから、テストが通るかどうかのように自動で確かめられる仕事ほど、周を重ねて良くなります。落ちたテストを直させるなら、テストを走らせる道具を渡します。「よく確かめて」と書き足すより効きます。

誤解「ループを回せば、Claude が自分で動き続けてくれる」 実際は回しているのはアプリのコード。次のリクエストを送らなければ、Claude は何もしない。止める条件も、アプリの側に書く。
