3-2　Claude Code の動かし方

ゴールセッション・コマンド・対話なしの実行・権限の任せ方を、場面で選び分けられる。

開発者→Claude Code

Claude Code は、画面で対話しながら使うほかに、CI やスクリプトから対話なしでも動かせます。どちらでも、何を確認なしで許すか（権限のモード）を決めてから動かします。

DOMAIN 3Claude Code Operation

モード確認なしで動くもの向く場面
default読み取りだけ1つずつ自分で確かめたい
acceptEdits読み取り・ファイルの編集・よく使うファイル操作見ながら直させる
plan読み取り。変更はしない変える前に調べて、計画を出させる
autoほぼすべて。裏で別のモデル（分類器）が見て、危ない操作だけを止める長い仕事で、確認の手間を減らす
dontAsk読み取りと、先に許可した道具だけ。確認が要るものは断る締めた CI やスクリプト
bypassPermissionsすべて隔離したコンテナや VM の中だけ

ポイント人が見ていない実行ほど、確認なしで許す範囲を狭くする。すべてを許すのは、隔離した環境の中だけ。

対話なしで動かす

ゴール対話なしの実行の書き方と、CI での注意を言える。

CI の手順から動かす

claude --bare -p "テストが落ちる原因を直して" \1
  --allowedTools "Read,Edit,Bash" \2
  --output-format json3
  1. 1-p で、1回の依頼を対話なしで実行して終わる。--bare を付けると、フック・Skills・MCP サーバ・CLAUDE.md などを読み込まない。
  2. 2確認なしで使わせる道具。人が承認できないので、先に決める。
  3. 3結果の形。json なら答えに費用やセッションの ID が付き、stream-json なら出来事が1行ずつ逐次で届く。

--bare を付けないと、-p はプロジェクトの設定にあるフックや MCP サーバも、信頼の確認なしに動かします。どのマシンでも同じ結果にしたい CI では、--bare で動かすのが安全です。

settings.json で決めておく

ゴールsettings.json に書く主な項目と、その効き方を言える。

.claude/settings.json

{ "permissions": {
    "allow": ["Bash(npm test *)"],1
    "deny": ["Read(./.env)"],2
    "defaultMode": "acceptEdits" },3
  "env": { "NODE_ENV": "test" } }4
  1. 1確認なしで許す操作。道具の名前と、引数の形で書く。
  2. 2禁止する操作。どのモードでも効く（bypassPermissions でも）。
  3. 3始めるときの権限のモード。
  4. 4セッションに渡す環境変数。

フック（〈決まった処理はフックで〉）やモデルも、ここに書きます。どのファイルの設定が勝つかは〈構成を管理する〉で扱いました。

セッションとコマンド

ゴールセッションの続け方と、組み込み・自作のコマンドの使い分けを言える。

コマンドすること
--continue直前の会話を続ける。--resume なら一覧から選ぶ
--fork-session続けるときに付けると、元の会話を残したまま、別の ID で枝分かれする
/compact会話を要約して窓を空ける。何を残すかを指示できる
/modelモデルを切り替える
/permissions許可・確認・禁止の規則を見て直す

自分で作るコマンドは、Skills として .claude/skills/名前/SKILL.md に書けば /名前 で呼べます（古い形の .claude/commands/ も使えます）。会話を分ける・捨てる判断は〈セッションとプラグインを管理する〉で扱いました。

誤解「CI では、止まらないように bypassPermissions で動かせばよい」 実際は人が見ていない場所で、すべてを許すことになる。使う道具だけを許し、それ以外は断らせる（dontAsk や --allowedTools）。
