3-1　Claude Code の部品

ゴール部品と CLAUDE.md の階層が、それぞれ何を担うかを言える。

開発者→Claude Code

Claude Code は、いつも守る決まり・必要なときだけの手順・呼び出す定型・別の窓で動く子・学んだことの記憶を、それぞれ別の部品としてファイルに置きます。どの部品に書くかで、いつ読まれ、誰が書くかが変わります。

DOMAIN 3Claude Code Operation

部品置き場所読まれる時書くもの
CLAUDE.md./CLAUDE.md など（AGENTS.md も読む）毎回、会話の最初にいつも守る決まり（ビルドの手順・書き方・構成）
Rules.claude/rules/*.md毎回。paths を付けると、合うファイルを読んだ時だけ話題ごと・場所ごとの決まり
Skills.claude/skills/名前/SKILL.md名前と説明は毎回、本文は要る時何段もある手順や参照資料。/名前 でも呼べる
Commands.claude/commands/*.md/名前 で呼んだ時定型の頼み方。いまは Skills と同じ扱いで、古い形として残る
Agents.claude/agents/*.mdClaude が任せると決めた時か、@ で名指しした時（別の窓で動く）子の役割・使える道具・モデル
Agent Memory~/.claude/projects/…/memory/索引（MEMORY.md）の先頭を毎回、細部は要る時Claude が学んだこと。Claude 自身が書く

ポイント毎回要る決まりは CLAUDE.md と Rules、要る時だけの手順は Skills、別の窓で任せる仕事は Agents。学んだことは、Claude 自身が記憶に書く。

CLAUDE.md の階層と、始め方

ゴールCLAUDE.md が読まれる順と、リポジトリでの始め方を言える。

置き場所ごとの効く範囲は〈構成を管理する〉のとおりで、見つかった CLAUDE.md は全部つなげて読まれます。作業しているディレクトリより上の CLAUDE.md は起動時に、下のディレクトリの CLAUDE.md は、そのディレクトリのファイルを読んだ時に読まれます。大きなリポジトリでは、決まりを使う場所の近くに置きます。

手すること
/initコードを調べさせ、ビルドやテストの手順を書いた最初の CLAUDE.md を作る。あれば直す案を出す
/memory置き場所ごとの CLAUDE.md と記憶のファイルを一覧し、開いて直す。自動の記憶のオン・オフも切り替える
/contextこのセッションに実際に読み込まれた CLAUDE.md と rules を確かめる
@path別のファイルの中身を、CLAUDE.md に取り込む

CLAUDE.md は毎回、窓を使います。公式の目安は1ファイル200行未満で、長いほど窓を使い、守られにくくなります。何段もある手順は Skills に分けます。

CLAUDE.md と記憶

ゴールCLAUDE.md と自動の記憶の違いを言える。

比べる点CLAUDE.md記憶（自動）
書く人利用者Claude
中身指示と決まり学んだことや、利用者に直されたこと
範囲プロジェクト・個人・組織リポジトリごと。その機械の中だけ

子（Agents）も、定義に memory を書けば、会話をまたいで残る自分専用の記憶を持てます。

誤解「CLAUDE.md や記憶に書いたことは、設定として強制される」 実際はどちらも文脈として読まれるだけ。必ず止めたい操作は、フック（PreToolUse）や権限の設定で止める。
