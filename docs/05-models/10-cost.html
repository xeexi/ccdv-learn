5-10　トークンを数え、費用を見積もる

ゴール使用量の記録から、1件あたり・1か月あたりの費用を見積もれる。

費用はトークンの数で決まります。見積もりに要るのは、1件あたり何トークン使ったかの実測と、単価だけです。

DOMAIN 5Cost and Token Management

応答に付く使用量

"usage": {
  "input_tokens": 1200,1
  "cache_creation_input_tokens": 0,2
  "cache_read_input_tokens": 3000,
  "output_tokens": 8003
}
  1. 1キャッシュを使わなかった入力だけの数。入力の合計は、入力の3つの欄を足したもの。
  2. 2キャッシュに書いた分と、キャッシュから読んだ分。どちらも、通常の入力とは単価が違う。
  3. 3出力。考えた分（思考）も、ここに含まれる。

ポイント使用量は応答ごとに返ってくる。これを記録しておけば、見積もりは推測ではなく実測から出せる。

見積もりの式

ゴール1件あたりと1か月あたりの費用を、使用量と単価から出せる。

求めるもの出し方
1件の費用入力トークン × 入力の単価 ＋ 出力トークン × 出力の単価（キャッシュの書き込みと読み出しは、それぞれの単価で）
月の費用1件の費用 × 月の件数

数える「1件」は、仕事が1つ完了するまでです。再試行、ツールとの往復、会話の往復も含めます。1回のリクエストが安くても、完了までに往復が増えれば高くつきます。

出力の単価は入力より高いので、長い出力や深い思考ほど効きます。記録は、機能や利用者ごとに分けて残します。どこで費用がかかっているかが分かれば、手を打つ場所が決まります。

下げる手効くところ
キャッシュ繰り返し送る長い指示や資料の、同じ前半（〈プロンプトキャッシュ〉）
Batch急がない大量の処理。通常の半額（〈まとめて安く〉）
effort考える量と前置きが多すぎる処理で、段階を下げる
区分評価で品質が保てると分かった処理で、下の区分に替える（〈モデルを選ぶ〉）

送る前に数える

ゴール送る前にトークン数を知る方法と、その注意を言える。

送る前に数えたいときは、トークン数を数える API（POST /v1/messages/count_tokens）に、送る予定の中身をそのまま渡します。数はモデルごとに違うので、実際に使うモデルを指定して数えます。他社のトークナイザで数えると、Claude の数とはずれます。数える API の数も見積もりで、実際とはわずかにずれることがあります。送った後は、応答の使用量が実際の数です（出力のうち考えた分は output_tokens_details の thinking_tokens に出ます）。

※ 単価はモデルごとに違い、改定もあるので、この教材には書きません。公式の料金表で確かめます。
