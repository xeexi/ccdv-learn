5-3　考えさせる量を選ぶ ─ thinking・effort・fast mode

ゴール4つの選択肢を、品質・待ち時間・費用のどれを動かすかで選び分けられる。

答える前に考えさせると、難しい問題の出来はよくなります。その代わり、考えた分のトークンと時間がかかります。どれだけ考えさせ、どれだけ急がせるかを決める手は4つです。

DOMAIN 5LLM Fundamentals

手決めること書き方
extended thinking
予算を決めて考えさせる		 考えに使うトークンの上限を、呼ぶ側が先に決める "thinking": {"type": "enabled", "budget_tokens": 8000}
古い世代の書き方。新しいモデルでは受け付けない
adaptive thinking
考える量をモデルが決める		 考えるかどうかと、どれだけ考えるかを、問題に応じてモデルが決める "thinking": {"type": "adaptive"}
いまの標準。常に有効なモデルもある
effort
力の入れ具合		 考える深さと、全体で使うトークンの目安（low 〜 max の段階） "output_config": {"effort": "low"}
fast mode
同じモデルを速く		 出力の速さ。速くなる代わりに、単価が上がる "speed": "fast"
研究プレビュー。使えるモデルと提供先が限られる

ポイントいまの形は「考えることはモデルに任せ（adaptive）、力の入れ具合を effort で決める」。fast mode は賢さではなく速さを買う手で、費用は上がる。

まず動かすのは effort

ゴールeffort を上げる場面と下げる場面を言える。

effort を下げると、考える量が減り、ツールの呼び出しもまとまり、前置きや確認の文も短くなります。同じモデルのまま、品質と、費用・待ち時間のかね合いを動かせるのが effort です。公式も、モデルを替えるより effort を調整するほうが効くことが多いとしています。

向き向いている仕事
上げるhigh 以上に。難しい推論、コーディング、長く自律的に動くエージェント
下げるlow・medium に。分類や短い応答、待ち時間に厳しい処理、子エージェントの単純な仕事

既定の段階はモデルによって違います。挙動をそろえたいなら、既定に頼らず明示します。

考えた分は、見えなくても払う

ゴール考えた分のトークンが、出力として数えられることを言える。

考えた内容は、応答の中に thinking という種類のブロックとして返ります。新しいモデルでは既定で中身が空のまま返り、要約を見たいときだけ表示を指定します。表示するかどうかに関係なく、考えた分は出力トークンとして数えられ、課金されます。出力の上限（max_tokens）も、考えた分と回答の合計に掛かります。

誤解「fast mode は、小さなモデルに切り替えて速くする機能」 実際は同じモデルのまま出力を速くする。そのぶん単価が高い。

※ 予算を決める方式（budget_tokens）は古い世代の書き方で、新しいモデルに送るとエラーになります。乗り換えで起きることは〈モデルを選ぶ・乗り換える〉で扱います。
