5-9　モデルを選ぶ・乗り換える

ゴールOpus・Sonnet・Haiku を品質・待ち時間・費用で選び、乗り換えで挙動が変わる危険に備えられる。

モデルは「いちばん賢いもの」を選ぶのではなく、課題に要る能力・速さ・費用のかね合いで選びます。

DOMAIN 5Model Selection and Tradeoffs

区分公式の位置づけ向く仕事の例
Opus
能力を優先		長く自律的に進めるコーディングや、知的作業のためのモデル大規模なリファクタリング、複雑なシステム設計、何時間も動くエージェント
Sonnet
均衡		速さと賢さの組み合わせが、最もよいモデル日々のコード生成、データ分析、ツールを使うエージェント
Haiku
速さと費用を優先		最も速く、最先端に近い賢さを持つモデルリアルタイムの応答、大量の処理、子エージェントの仕事

ポイント区分が上がるほど賢くなり、遅く、高くなる。どの区分が合うかは、課題と予算で決まる。

※ 区分の顔ぶれと名前は世代で変わります（いまは Opus のさらに上に、最も難しい推論に向けた区分もあります）。最新の一覧は、公式のモデル一覧で確かめます。

2つの始め方

ゴール小さいモデルから始める場合と、大きいモデルから始める場合を選び分けられる。

考え方の対応（adaptive thinking など）も、モデルごとに違います。たとえば小さい区分には、予算を決める古い方式でしか考えられないものがあります。使いたい機能に対応しているかは、Models API の capabilities か、公式の一覧で確かめます。

乗り換えで壊れるもの

ゴール新しい版に替えたときに起きうる変化と、その備えを言える。

同じ区分の新しい版でも、同じリクエストが同じようには動かないことがあります。起きる変化は3種類です。

変化例備え
エラー古い書き方の指定を受け付けない（予算を決める思考、temperature の指定、応答の書き出しを先に埋める指定）まず1件だけ送って確かめる
無言の変化既定値が変わる（思考の表示、既定の effort）。同じプロンプトの効き方も変わり、強い口調の指示が効きすぎることもある自分の用途の評価セットで、旧版と比べる
数え方トークンの区切り方が変わり、同じ文でもトークン数が増減するトークン数を数え直し、出力の上限と費用の見積もりを直す

備えの土台は、版を固定しておくことです。モデル ID は版ごとに固定された名前なので、いつ替えるかをこちらで決められます（〈版を固定する〉）。

ポイント乗り換えは、同じ区分の新しい版でも挙動が変わる。まず1件、次に評価セット、トークン数も数え直してから切り替える。
