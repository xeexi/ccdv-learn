DOMAIN 5Technical Fundamentals

SSE で届くもの

ゴール逐次で受け取ると、どんな順で何が届くかを言える。

"stream": true を付けて呼ぶと、1つの HTTP 応答の中にイベントが順に流れてきます。始まり、ブロックの始まり、本文の差分の繰り返し、ブロックの終わり、止まった理由と使用量、終わり、という順です。

event: message_start
event: content_block_start
event: content_block_delta   # 本文の差分。これが何度も来る
event: content_block_stop
event: message_delta         # stop_reason と使用量
event: message_stop

差分をつなぎ合わせて元の応答を組み立てる方法と、途中で切れたときの立て直しは〈逐次で受け取る〉で扱います。

WebSocket が要るのは、双方向が要るとき

ゴールWebSocket を選ぶ理由と、Claude の API との位置関係を言える。

SSE はサーバから届くだけの一方向です。途中で利用者からサーバへ何かを届けたくても、同じ接続では送れません。音声を送り続けながら返事も受け取る、といった双方向の常時接続が要る画面では、ブラウザと自分のサーバの間を WebSocket でつなぎます。

そのときも、自分のサーバから Claude の API へは HTTP（逐次なら SSE）で呼び、受け取ったものを WebSocket で画面へ流します。WebSocket は、アプリの内側の配線です。

誤解「逐次で受け取るには、Claude の API に WebSocket でつなぐ必要がある」 実際はClaude の API の逐次の受け取りは SSE。WebSocket を使うのは、自分のアプリの中で双方向が要るとき。

ポイント1往復で足りるなら REST、できた端から見せたいなら SSE、双方向に常時やり取りするなら WebSocket。Claude の API 自体は HTTP と SSE で完結する。

※ 長い出力を1往復で待つと、途中の経路や SDK の待ち時間の上限にかかりやすくなります。長くなりそうな呼び出しは、逐次で受け取るのが安全です。
