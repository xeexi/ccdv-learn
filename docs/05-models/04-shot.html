5-4　例を何個見せるか ─ zero・single・multi-shot

ゴール例の数を増やす得と損を言い、課題に合う数を選べる。

指示だけで頼むか、手本を見せて頼むか。プロンプトに入れる手本（例）の数で、呼び名が変わります。

DOMAIN 5LLM Fundamentals

呼び名例の数向いている場面気をつけること
zero-shot0指示だけで伝わる、よくある作業（要約・翻訳）出力の形や、判断の基準が揺れやすい
single-shot1出力の形を1つ見せれば足りる例の話題や長さまで真似しやすい
multi-shot複数形をそろえたい、判断の境目を教えたい例の分だけ、毎回の入力トークンが増える

ポイント例は「形」と「判断の境目」をいちばん短く伝える手段。ただし毎回の入力に乗るので、足りない分だけ足す。

例が効くわけ

ゴール例が出力を寄せる仕組みを、次のトークンの選び方で説明できる。

モデルは、ここまでの文章から次に来そうなトークンを選びます（〈次の1トークンを選び続ける〉）。手本が入っていると、手本と同じ形の続きが「もっともらしく」なるので、出力がそちらに寄ります。

裏返すと、手本の意図しない特徴まで真似されます。例がどれも短ければ出力も短くなり、同じ話題ばかりなら話題も寄ります。複数見せるなら、互いに違う例を選びます。例の書き方は〈はっきり頼む〉で扱います。

例は安くない

ゴール例を足す費用と、その抑え方を言える。

API は会話を覚えていないので、例も毎回の入力として送り直されます。件数の多い処理では、例の分のトークンがそのまま件数倍になります。

例のように毎回同じ部分は、プロンプトの前のほうに置けばキャッシュでき、2回目からは安く読めます（〈プロンプトキャッシュ〉）。
