5-6　SDK は REST を包んでいる

ゴールSDK の1回の呼び出しが、どんな HTTP リクエストと応答になるかを言える。

アプリ→Claude→アプリ

SDK は、HTTP で API を呼ぶ手間を肩代わりしてくれる部品です。中で起きていることは単純で、決まった URL に JSON を送り、JSON を受け取るだけです。

DOMAIN 5Technical Fundamentals

SDK で書く（Python）

client = anthropic.Anthropic()   # 鍵は環境変数から読む
msg = client.messages.create(1
    model="claude-sonnet-5",
    max_tokens=1024,
    messages=[{"role": "user", "content": "こんにちは"}],
)

実際に送られる HTTP

POST https://api.anthropic.com/v1/messages
x-api-key: …2
anthropic-version: 2023-06-01
content-type: application/json

{ "model": "claude-sonnet-5",3
  "max_tokens": 1024,
  "messages": [{ "role": "user", "content": "こんにちは" }] }

返る JSON（要所だけ）

{ "type": "message", "role": "assistant",
  "content": [{ "type": "text", "text": "こんにちは。…" }],4
  "stop_reason": "end_turn",
  "usage": { "input_tokens": 12, "output_tokens": 20 } }
  1. 1メソッド1つが、エンドポイント1つに対応する。messages.create は POST /v1/messages。
  2. 2認証は API キーのヘッダで行う。anthropic-version は、やり取りの形式の版。
  3. 3本文で必須なのは model・max_tokens・messages の3つ。モデルもヘッダではなく本文で指定する。
  4. 4答えは content の中にブロックの配列で入る。止まった理由と使用量は、その外側に付く。

ポイントSDK の呼び出し1回は、API への JSON の往復1回（POST /v1/messages）。SDK を外しても、同じ JSON を送れば同じように動く。

SDK が肩代わりしていること

ゴールSDK を使うと自分で書かずに済むものを挙げられる。

項目SDK を使うとHTTP を自分で書くと
鍵とヘッダ環境変数から鍵を読み、ヘッダを付ける毎回自分で付ける
再試行一時的な失敗（混雑・サーバ側の不調・接続の切断）を、間を空けて既定で2回までやり直す自分で書く
待ち時間既定の上限を持つ。長い出力には、逐次で受け取る書き方を勧める自分で決める
型の誤り型の補完で、書いた時点で気づけるJSON を手で組む
エラー種類ごとの例外で受け取れるステータスコードを読んで分ける

再試行を二重にしない

ゴールSDK の再試行の上に自前の再試行を重ねると何が起きるかを言える。

SDK の中ですでに再試行しているのに、呼ぶ側でも「失敗したら3回やり直す」を書くと、試行の回数が掛け算で増えます。混雑しているときほど送信が増え、待ち時間も上限の数倍まで伸びます。

やり直しはどちらか1か所に置きます。SDK に任せるなら、回数と待ち時間の上限を SDK の設定で決め、呼ぶ側では、やり直しても直らない失敗だけを扱います。失敗の種類の見分け方は〈エラーの種類と、立て直し方〉で扱います。

※ SDK は Python・TypeScript など主な言語ごとにあり、どれも同じ API を呼びます。モデル ID は例で、世代で変わります。他社のクラウド経由で呼ぶときは、そのクラウド向けのクライアントを使います（〈データの渡し方と、呼び出し口〉）。
